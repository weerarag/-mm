# เกมจำลองเครื่องวัดความดัน — Design

ซีรีส์เกม "จำลองกลไกเครื่องมือแพทย์" ทำทีละเครื่อง เครื่องแรกคือเครื่องวัดความดันโลหิตแบบพันแขน

## Intent / Why
ผู้เล่นคือ **พยาบาล** และ **วิศวกรชีวการแพทย์** ต้องการให้เข้าใจครบสามชั้น:
1. หลักการและกลไกของเครื่อง (ปั๊ม วาล์ว เซนเซอร์ความดัน cuff)
2. การทำงานร่วมกับลักษณะทางคลินิก (เคสผู้ป่วย ข้อผิดพลาดที่พบบ่อย)
3. ค่าที่อ่านได้มาจากไหน (Korotkoff, oscillometric envelope, MAP)

## Goals
- เครื่องจำลองเดียวจากแบบจำลองสรีรวิทยาเดียว (ความดันในหลอดเลือดต่อจังหวะหัวใจ + ความดันใน cuff) ใช้ร่วมสองโหมด
- **โหมดพยาบาล (manual/auscultatory):** ปั๊มลมด้วยมือ ปล่อยลมด้วยวาล์ว ฟังเสียง Korotkoff (เล่นเสียง + แสดงภาพ) อ่านค่า systolic = เสียงแรก, diastolic = เสียงหาย; มีหน้าปัดเข็ม/คอลัมน์ปรอท
- **โหมดวิศวกร (automatic/oscillometric):** ปั๊มและปล่อยลมอัตโนมัติ แสดงสัญญาณความดัน cuff, oscillation (band-pass) และ envelope; หา MAP จากจุดสูงสุด คำนวณ SBP/DBP ด้วยอัตราส่วนลักษณะเฉพาะ (ค่าประมาณ ปรับได้ ระบุว่าแต่ละผู้ผลิตต่างกัน)
- สลับมุมมองได้: ภายนอก (แขน+cuff) / กลไก (ปั๊ม วาล์ว เซนเซอร์ ADC บล็อกไดอะแกรม) / สัญญาณ (คลื่นและเสียง)
- **ด่านเคสผู้ป่วย** เล่นได้ทั้งสองโหมด: ความดันสูง, ความดันต่ำ, auscultatory gap, หัวใจเต้นไม่สม่ำเสมอ (เช่น AF), แขนอ้วน/ผอม
- **ข้อผิดพลาด (ลองทำเอง):** ปล่อยลมเร็วเกินไป (ค่าต่ำเกินจริง), cuff เล็กเกินไป (ค่าสูงเกินจริง), แขนต่ำกว่าระดับหัวใจ (สูงเกินจริง), วัดซ้ำทันที; เกมอธิบายสาเหตุหลังจบด่าน
- ให้คะแนน/ฟีดแบ็ก: เทียบค่าที่ผู้เล่นอ่านกับค่าจริงของเคส (ยอมรับ ±5 mmHg) และอธิบาย "ค่านี้ได้มาอย่างไร"
- ภาษาไทยเป็นหลัก ศัพท์เทคนิคคงอังกฤษ

## Non-goals / Anti-goals
- ไม่ใช่เครื่องมือวินิจฉัยหรือทดแทนการอบรมทางคลินิกจริง; ใส่คำเตือนชัดเจน
- ไม่เลียนอัลกอริทึมเฉพาะของยี่ห้อใด
- ไม่ทำโหมดประกอบ/ซ่อมเครื่อง (โหมด C) ในรอบนี้
- Anti-goal: เกมที่กลายเป็นแค่ตอบคำถามโดยไม่เห็นกลไก; ภาพสวยแต่ฟิสิกส์ผิด

## Constraints
- เว็บเกมไฟล์ HTML เดียว (HTML/CSS/JS ล้วน ไม่มี dependency/build) เปิดในเบราว์เซอร์ได้เลย; เสียงด้วย Web Audio API
- โครงสร้างโค้ดแยกเป็นโมดูลภายในไฟล์ (แบบจำลองสรีรวิทยา / เครื่อง / UI) เพื่อนำ engine ไปใช้ต่อกับเครื่องถัดไป
- ใช้งานได้บนมือถือและเดสก์ท็อป

## Approaches (พิจารณาแล้ว)
- A ห้องทดลองอิสระ — ง่าย แต่ไม่มีโจทย์
- B เกมด่านเคส — ได้ความรู้ทางคลินิก แต่ต้องมีเครื่องจำลองรองรับ
- C โหมดวิศวกรประกอบ/ซ่อมเครื่อง — ลึกด้านกลไก แต่พยาบาลเข้าถึงยาก
- **เลือก A+B** (ผู้ใช้เห็นด้วย) เลื่อน C ไปรอบถัดไป

## การตัดสินใจของผู้ใช้
- ผู้เล่น: พยาบาลและวิศวกรชีวการแพทย์
- เนื้อหา: หลักการ กลไก ความเชื่อมโยงทางคลินิก ที่มาของค่า
- โครงสร้าง: A+B, ทำทีละเครื่อง เริ่มจากเครื่องวัดความดัน

## การตัดสินใจของผม (ตรวจได้)
- เว็บ HTML ไฟล์เดียว, ภาษาไทย
- ช่วงยอมรับค่าที่อ่าน ±5 mmHg
- ใช้อัตราส่วน oscillometric ประมาณ SBP ≈ 0.55 และ DBP ≈ 0.75 ของแอมพลิจูดสูงสุด (ปรับได้)
- ตำแหน่งไฟล์: `games/bp-monitor/index.html`

## ปล่อยให้ผู้สร้างตัดสินใจ
รายละเอียดภาพ/UI, รูปแบบเสียง, จำนวนและลำดับด่านเคส (อย่างน้อย 5), ถ้อยคำคำอธิบาย
